# 執行紀錄

正式 CLI 的執行紀錄存放在 `logs/<命令名稱>/<UTC 日期>/`。每次啟動建立一個獨立的 JSON Lines 檔案；檔名包含 UTC 時間與隨機識別碼，避免覆寫。同一命令的不同執行，以及不同命令的紀錄，都分開存放。

本專案的原始碼執行環境以 `run_logging.py` 的位置定位專案根目錄，因此從其他工作目錄啟動仍會寫回本目錄。若將套件安裝為獨立 wheel，模組位置會改變，需另行設定適合的 log 根目錄。

目前 `auto-link-unprocessed-fault-notices-to-daily-inspection-work-orders` 記錄批次識別碼、來源筆數、逐筆查詢條件與結果摘要、選取的工單、勾稽結果，以及安全化的錯誤訊息。每一行是一個 JSON 物件，可用 `run_id` 或 `fault_notice_no` 尋找相關事件。正式 CLI 的 stdout 仍只輸出原有 JSON 結果。

Log 檔含內部通報號與工單號。`logs/` 下的執行檔案不納入 Git；不要將檔案轉存到公開位置。紀錄不包含帳密、cookie、token、完整 MMIS 回應或完整來源通報資料。目前沒有自動刪除機制。

查詢結果為零筆的事件能證明該次查詢使用的條件與程式收到的筆數，不能單獨證明 MMIS 中被排除工單當時的狀態。

若檔案開啟後發生寫入錯誤，程式會在 stderr 顯示一次「紀錄可能不完整」警告。MMIS 批次仍依既有勾稽結果完成，該次 log 可能缺少後續事件。
