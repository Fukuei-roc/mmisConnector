# 功能規格書：故障分析素材

## Metadata

- 功能：完整故障通報查詢新增故障分析素材
- 負責人：專案使用者／Codex
- 狀態：使用者已明確核准實作（2026-10-14）
- 風險等級：高（使用既有 MMIS 認證與唯讀網路查詢）

## 問題與目標

完整通報 JSON 已有段修工單，但下游分析仍需逐一另查工單明細。使用者以原 CLI 查詢通報時，需要保留原有頂層資料並在最後取得三類工單的指定欄位。

## 非目標

- 不修改原通報欄位、既有三類工單 Reader 的輸出契約或 MMIS 遠端資料。
- 不加入平行查詢、瀏覽器流程或新的 HTTP 協定實作。

## 資料與 API

- 輸入：`query_fault_notice_full_detail <通報號>`。
- 類型：工作單號第二段為 `C1/C2/C3`、`1A`、`2A/3A`；工單級別欄位不參與判斷。
- 輸出：原 JSON 最後新增 `故障分析素材`，固定含 `臨時檢修工單`、`日檢工單`、`定期檢修工單` 三個陣列。
- 成功資料：臨修保留 `work_order`、車組/車號、故障現象、原因說明、備註、維修程序概況；日檢保留工作單、車組/車號、檢修記錄、重要事項紀錄；定檢保留工作單、車組/車號、維修程序概況、檢修記錄、維修情形、維修情形(詳述)。巢狀 records 與文字原樣保留。
- 失敗資料：僅工作單號、`查詢狀態=失敗`、`錯誤訊息`；其他工單繼續查詢。
- 缺少成功欄位時，文字為 null，巢狀為空 count/records。

## 驗收標準

- 三類皆為陣列且依段修工單原順序排列；重複號碼只查一次，但仍保留每次出現。
- 暫時性網路失敗最多三次：第一次後立即重試，第二次後等待一秒；非網路錯誤不重試。
- 原頂層資料不改；stdout 為單一合法 JSON；診斷資訊在 stderr。
- 模擬上述情境並以指定通報號做可用時的唯讀實際查詢。

## 安全性與隱私

- 共用單一 `MMISSession`，登入憑證只由既有環境設定載入。
- 工作單查詢仍經既有同源 HTTPS Client；不存放通報明細於檔案。
- 網路重試只套用唯讀工單明細流程；若回應明確顯示登入或權限錯誤，不重試。
