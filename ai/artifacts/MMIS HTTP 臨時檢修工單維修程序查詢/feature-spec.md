# 功能規格書

## Metadata

- 功能：依工作單查詢臨時檢修工單的維修程序概況
- 負責人：Codex
- 狀態：已實作（使用者於 2026-10-05 提出明確實作要求）
- 風險等級：中；沿用既有認證和 HTTPS 存取，唯讀

## 問題與目標

內部使用者需要用一個工作單號取得工單基本資料、已勾稽故障通報，以及「檢修回報」頁籤中「紀事(備註)清單」所有紀錄，直接從 stdout 讀取 JSON。

## 非目標

- 不修改 MMIS 資料、不下載報表、不產生檔案。
- 不新增瀏覽器自動化或正式 `mmis-connector` CLI 子命令。

## 使用者故事

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 查詢維修程序 | 內部使用者輸入工作單並取得全部紀事欄位，以便分析維修程序 | 一筆、多筆與空清單都有一致 JSON 契約 |

## 使用者旅程

輸入 `python -m tools.mmis_development.query_temporary_repair_work_order_maintenance_procedure_summary 115-C2-41266` → HTTP 登入 → 開啟臨時檢修工單 → 唯一且完全相符篩選 → 檢修回報 → stdout JSON。

## 功能需求與資料契約

- 輸入：一個工作單號，trim 後只允許 ASCII 英數字與連字號。
- 查詢固定限定檢修級別 `C1,C2,C3`，工作單完全相符且清單唯一才開啟明細。進入臨時檢修工單後先在預設清單過濾；只有確認第一輪結果為 0 筆時，才切換「所有記錄」並重設相同過濾條件。第二輪仍為 0 筆時回報找不到工作單；結果不唯一、與輸入不符或分頁不一致時直接報錯，不因結構異常而回退。
- 最上層輸出：`success`、`query_name`、`work_order`，以及工單明細的 `車組/車號`、`檢修級別`、`故障現象`、`原因說明`、`備註`、`檢修日期`、`完工日期`、`工作單狀態`。八個基本欄位均為字串；空白欄位保留空字串，備註保留換行。
- `已勾稽故障通報` 位於最上層的 `工作單狀態` 之後、`維修程序概況` 之前，格式為 `{"count": 整數, "records": 清單}`。每筆保留明細表的 `故障通報號`、`發生日期`、`車組/車號`、`故障現象`、`事故等級`；空清單為 `{"count": 0, "records": []}`。以日檢工單相同的「故障通報管理」表格與欄位解析，分頁超過單頁或筆數不一致時拒絕回傳部分資料。
- `維修程序概況` 為最上層物件，包含 `count` 與 `records`。`records` 每筆含車組/車號、故障類別、故障類別說明、故障現象、故障原因、處置措施、維修程序、材料編號(PA)、更換數量，值均為字串。空清單為 `"維修程序概況": {"count": 0, "records": []}`。
- `試車報告` 位於 JSON 最後，格式為 `{"count": 整數, "records": 清單}`。從「檢修回報」頁籤的「工作單的子項」表格只保留檢修內容完全等於「試車報告」的子單。每筆依序包含工作單、檢修內容、車組/車號、檢修廠段、檢修單位、工作單狀態，值均為字串；零筆時為 `{"count": 0, "records": []}`。讀取全部分頁，若頁數或總筆數不一致則報錯，不回傳部分結果。
- 基本資料以工單明細的標籤與控制項對應擷取。日期優先使用輸入值，其次使用顯示用 `title`，最後由 `dojovalue` 毫秒時間戳轉為台北日期 `YYYY/MM/DD`；同名重複日期欄位必須一致。
- MMIS 可能使用「故障類型說明」或「故障類別說明」，輸出統一為「故障類別說明」。表格有逐列「車組/車號」時以逐列值為準，否則使用工單明細的車號。
- 當紀事列的「故障現象」為「其它問題」或「其他問題」時，讀取該列明細中標籤「其它故障現象」對應的 textarea；內容非空時以全形冒號接在原值後面。逐列切換以確保不混用另一筆的補充文字。
- 當「故障原因」為「其它原因／其他原因」、或「處置措施」為「其它／其他」時，分別讀取「其它故障原因」與「其它處置措施」textarea，非空內容同樣以全形冒號接在選項後面。三欄在同一次選列後讀取。
- Maximo 切換列時可能只回傳選列確認、不重送值未改變的 textarea；此時沿用畫面已渲染的補充值。空補充值不加冒號。若未確認選列成功，不回傳可能錯列的資料。
- 錯誤：參數、零命中、重複命中、表格缺失與分頁不一致時輸出 JSON 錯誤且 exit code 1。

## 安全性與隱私

- 沿用 `MMISSession` 的 `.env` 憑證載入、同源 HTTPS 與 session 生命週期。
- 不保存 HAR、cookie、token 或查詢結果；stdout 僅輸出業務 JSON。

## 驗收與驗證

- 基本資料 HAR 與 DOM 錄製均能取得八欄；指定維修程序 HAR 離線重放可取得 2 筆，九欄值與錄製一致。
- `115-C1-41264` 即時查詢回傳八欄基本資料與 1 筆紀事；`115-C2-41266` 即時查詢仍回傳全部 3 筆紀事。
- `115-C1-41264` 的明細錄製與即時查詢均取得 1 筆已勾稽故障通報；`115-C2-41266` 的原錄製明細為空通報清單。
- 速度優化錄製：`115-C1-41264` 在預設清單直接找到；`115-C1-36682` 預設清單 0 筆，切換「所有記錄」後找到。兩條路徑均保留原有 JSON 契約。
- 空清單、無效參數及結構異常可安全處理。
- 完整 `pytest`、編譯與 diff 檢查通過。
- `115-C2-41283` 即時查詢取得 `115-C2-41283-001` 試車報告；`115-C2-41266` 無試車報告時仍成功並回傳空物件清單。
