## 目標

`--export-xlsx` 在既有輸出目錄產生兩個 Excel 檔案。

## 情境包（Context Pack）

- 相關檔案：同步工具、既有 SQLite 匯出器、共用 Excel 建構器、兩種工單查詢工具、`.env.example` 與測試。
- 既有模式：SQLite 工單欄是 JSON 字串陣列；匯出工具透過 `.env` 指定輸出目錄，使用 openpyxl 文字儲存與樣式。
- 假設：組長姓名是環境設定；1A 的檢修段為精確字串比對；工單號依首次出現順序去重。
- 未知事項：正式 MMIS 下次執行時的工單及待簽核人資料。
- 允許變更的檔案：上述工具、測試、環境範例及本 Epic 的規格與驗證文件。
- 不得觸碰：正式 SQLite 資料、MMIS 查詢元件契約、不相關檔案。
- 情境預算：讀取專案地圖、流程、DoR、DoD、相關工具與測試；略過無關 UI 與其他查詢模組。

## 需求

- 解析全部待簽核工單、去重後查詢 C 級及 1A 明細。
- 以組長姓名及 1A 檢修段規則篩選。
- 沿用既有 Excel 文字格式、字型、對齊及檔名日期與衝突處理方式。

## 驗收標準

- 加旗標執行後 JSON 回應列出兩個報表，兩者在同一目錄。
- 重複工單只查詢及輸出一次；不符合簽核人或 1A 段別者不輸出。
- 缺少必要設定或查詢回應無效時清楚失敗。

## 實作備註

- 資料契約：SQLite `待簽核工單` 為 `NULL` 或 JSON 字串陣列；明細回傳 `工作單`、`待簽核人`，1A 另有 `檢修段`。
- 不變更資料庫模型、遠端權限及既有 MMIS 寫入路徑。

## 驗證契約

- 單元測試：去重、雙類型篩選、空清單、異常回應、Excel 樣式。
- 整合測試：離線替身同步與雙報表輸出。
- E2E 測試：不執行正式同步，以免觸發既有 MMIS/AI 寫入。
- 型別檢查：不適用，專案未設定靜態型別工具。
- Lint：`git diff --check`。
- Build：Python 編譯檢查。
- 螢幕截圖：不適用，無 UI。
- 安全性檢查：姓名由 `.env` 載入；不記錄憑證。
