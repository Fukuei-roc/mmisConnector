# 清查逾期工單功能規格

## Metadata

- 功能：清查逾期工單（Audit Overdue Work Orders）
- 狀態：已實作，依使用者本次明確需求執行
- 風險等級：高，涉及 MMIS 網路查詢與本機資料庫覆蓋

## 問題與目標

使用者需要將 MMIS「工單逾期查詢」結果保存為每次重建的本機快照，供後續清查使用。

## 使用者與故事

內部操作人員執行單一命令後，取得當次查詢的全部結果頁及可編輯的空白備註欄。

## 功能需求

- 查詢畫面的車組(輛)、檢修級別、工單編號、工單狀態、人員、檢修日期、完工日期、逾期天數。
- 逐頁讀取並驗證分頁範圍、總筆數與工單編號唯一性。
- 完整查詢成功後，以交易重建 `data/overdue_work_orders.db` 中的資料表。備註預設為空字串。
- 逾期清單查詢或快照寫入失敗時保留上次成功的快照。
- 快照建立後，依資料庫順序查詢檢修級別為 `2A` 或 `3A` 的主工單，使用完整定期檢修工單狀態查詢元件取得子工單。
- 排除子工單狀態 `核簽中` 與 `工單結案`；其餘以 `工作單(工作單狀態)` 形成備註，多筆以半形逗號連接。沒有符合項目時備註維持空白。
- 查詢全部完成後一次寫入備註，並列印所有備註非空的完整資料列。單筆狀態查詢失敗時命令失敗，已建立的當次快照保留空白備註。

## 非目標

- 不修改 MMIS 工單。
- 不保存前次備註，不新增畫面或 Excel 匯出。

## 資料與 API

- 輸入：MMIS 環境憑證，命令不接受參數。
- 輸出：`overdue_work_orders` 資料表，欄位依需求順序加上最後的「備註」。
- 驗證：八欄存在、分頁完整、工單編號非空且唯一。
- 錯誤：非零結束碼。逾期清單查詢或快照寫入失敗時保留舊快照；子工單狀態查詢失敗時保留當次新快照與空白備註。

## 安全性與驗收

沿用既有 MMIS session；資料庫僅寫入本機 `data`。錄製 HAR 不納入程式或版本控制。驗收以錄製頁解析、SQLite 交易測試及 Live 唯讀查詢為準。
