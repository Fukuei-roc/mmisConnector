# 功能規格書

## Metadata

- 功能：自動刪除重複開立的日檢工單，查詢快照與取消候選判定
- 英文名稱：Auto Delete Duplicate Daily Inspection Work Orders
- 狀態：使用者於 2026-11-09 要求在快照候選判定後自動取消工單
- 風險等級：高，涉及 MMIS 登入、網路及本機資料庫

## 問題與目標

內部使用者需要取得新竹機務段「執行中未派工」日檢工單，判定同車組的重複工單，並取消已確認的舊工單。

## 功能需求

- 執行 `python -m tools.mmis_development.auto_delete_duplicate_daily_inspection_work_orders`，不帶參數。
- 查詢 MMIS 動力車日檢(1A)，條件為配屬段「新竹機務段」及工作單狀態「執行中未派工」。
- 擷取全部頁面，每筆保留車組/車號、工作單、預計檢修(進廠)日。
- 完整查詢成功後，以 SQLite 交易替換舊快照。每筆另存查詢時間，執行結果預設為空白。
- 新快照欄位依序為「車組/車號、工作單、預計檢修(進廠)日、查詢時間、開單日期、執行結果」；新快照的開單日期與執行結果預設為空白。
- 只對有多筆資料的非空白「車組/車號」查詢各工作單明細，並保存 MMIS 回傳的開單日期。
- 同組所有日期都成功且最新日期唯一時，保留最新工單；其餘資料列的「執行結果」寫入「待工單取消」。
- 非空白「車組/車號」僅有一筆時，將該列「執行結果」寫入「無重複」，且不查詢工單明細。既有 SQLite 快照中的單筆車號也依相同規則補寫。
- 任一工單日期查詢失敗或日期缺失時，該組不標記取消；最新日期並列時亦不任意選擇。
- 快照與候選判定完成後，依資料庫列順序處理「執行結果」為「待工單取消」的工作單。重用同一 MMIS session，使用既有取消元件檢查工單仍為「執行中未派工」，以「重複開單」為理由取消，並回讀確認狀態為「工單取消」。
- 每筆確認成功後，將該列「執行結果」更新為「已取消工單」；任何取消或回讀失敗時停止整批，保留其餘待取消列供人工檢查。
- 完成後若沒有重複車組，印出「未發現重複的未派工日檢工單」；若有工單確認取消，逐筆印出「已刪除的車組/車號：<車組/車號>，工作單：<工作單>」。
- 印出總筆數。查詢或入庫失敗時不得清掉前一次成功快照。

## 非目標

- 不刪除當次快照中的資料列。下一次執行仍依既有流程替換舊快照。
- 不對只有一筆資料的車組查詢開單日期。
- 無 UI。

## 驗收標準

- 超過 30 筆時逐頁讀完，筆數須等於 MMIS 顯示總數。
- 重跑及零筆結果會替換舊資料；失敗則保留舊資料。
- 資料庫有指定六欄及順序，指令印出總筆數與重複判定摘要。
- 指定里程碑為 EMU929／115-1A-81454 標記「待工單取消」。但 2026-11-04 的 MMIS 實際查詢顯示該工單開單日期晚於同組 115-1A-80361，因此與「保留最新工單」規則衝突，需使用者決定優先規則。
- 日期查詢不完整或最新日期並列時，不得為該車組標記取消。
- 只有遠端工單狀態確認為「工單取消」的列會寫成「已取消工單」；取消失敗時不繼續下一筆。
- 沒有重複車組時，stdout 含指定的未發現訊息；有已取消工單時，stdout 含對應的車組與工作單。

## 安全性與驗證

- 查詢與取消重用一個 MMIS session；資料庫由 Git 忽略，SQL 值使用參數綁定。取消事件不得自動重送。
- 用合成跨頁與取消結果測試驗證；Live 取消會修改 MMIS，需以受控工單另行驗證。無畫面截圖需求。
