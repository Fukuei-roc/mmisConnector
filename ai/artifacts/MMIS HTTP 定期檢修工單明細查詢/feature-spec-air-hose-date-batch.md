# 功能規格書：自動查詢空氣軟管日期

## Metadata

- 功能：批次查詢定期檢修工單空氣軟管日期並回填 Excel。
- 負責人：專案使用者。
- 狀態：依使用者 2026-10-27 明確要求新增程式、實作與驗證，目標行為已核准；續跑狀態的內部存放方式交由架構規劃決定。
- 風險等級：高，使用 MMIS HTTPS session 並寫入本機活頁簿；遠端操作唯讀。

## 問題

使用者目前需要逐筆取得配屬車號總表中的工作單，再查詢附表一的空氣軟管日期資料，並把每筆檢查項目和量測值整理到另一個活頁簿。手動逐筆處理耗時，網路中斷也可能讓已完成進度難以辨識。

## 使用者

需要定期整理配屬車號總表之空氣軟管日期的內部 MMIS 使用者。

## 目標

- 新增名為「自動查詢空氣軟管日期」的 development tool。
- 逐筆讀取來源活頁簿的「工作單」，呼叫現有空氣軟管日期查詢 component。
- 把來源資料、查詢車型、所有「檢查項目」和「量測值」寫入目標活頁簿。
- 網路或 session 查詢失敗時重試；仍失敗的資料列可在下次執行繼續查詢。

## 非目標

- 不修改 MMIS 工單、檢修回報或其他遠端資料。
- 不更改既有單筆空氣軟管日期查詢工具的資料契約。
- 不新增瀏覽器自動化、production CLI 命令或排程服務。
- 不改動兩個指定活頁簿以外的使用者檔案。

|---|---|---|

## 使用者旅程

```text
使用者執行「自動查詢空氣軟管日期」程式。
程式驗證來源與目標活頁簿，逐筆查詢工作單並保存結果。
遇到網路失敗時程式重試。仍失敗的工作單留待下次執行。
使用者查看目標活頁簿和本次執行摘要。
```

## 功能需求

- WHEN 使用者不帶參數執行新工具，THE SYSTEM SHALL 使用指定的來源和目標活頁簿路徑。
- WHEN 來源工作表標題符合預期，THE SYSTEM SHALL 依序讀取每筆來源資料的「車組/車號」、「檢修級別」、「工作單」和「檢修日期」。
- WHEN 查詢工作單成功，THE SYSTEM SHALL 為該工單的每筆 `records` 輸出一列，欄位順序為「車組/車號」、「車型」、「檢修級別」、「工作單」、「檢修日期」、「檢查項目」、「量測值」。
- WHEN 工作單查詢暫時失敗，THE SYSTEM SHALL 最多重試三次，並在重試後仍失敗時繼續處理後續工作單。
- WHEN 執行中斷或部分工作單查詢失敗，THE SYSTEM SHALL 保留已成功資料與完成狀態，並讓下次執行從未完成工作單繼續。
- WHEN 工作單查詢成功但結果為不支援車型或零筆，THE SYSTEM SHALL 記錄該工作單已完成，避免續跑時將它誤認為尚未查詢。
- WHEN 程式輸出摘要，THE SYSTEM SHALL 列出失敗、不支援與零筆結果的來源列；不支援和零筆狀態包含先前執行已保存的完成項目。
- WHEN 來源活頁簿標題或結構不符，THE SYSTEM SHALL 在任何輸出修改前停止並回報錯誤。
- WHEN 最終仍有失敗工作單，THE SYSTEM SHALL 回報其來源列和失敗數量，並以非零結束碼結束。

## 資料與 API

- 輸入：`最新檢修工單` 工作表的四個欄位；現有 `run_air_hose_dates(work_order)` 回傳的車型與 records。
- 輸出：`空氣軟管日期` 工作表七欄資料；續跑狀態需與成功資料一併保存。
- 驗證：副檔名、檔案可讀性、指定工作表、完整欄名、非空工作單，以及來源快照一致性。
- 錯誤：格式錯誤、檔案存取錯誤、查詢失敗、重試耗盡、來源變更與輸出保存失敗均明確回報；失敗不得標記完成。
- 重試：最多三次；沿用既有批次 query/session 重建模式。架構階段需確認可重試錯誤範圍與單筆查詢錯誤型態。
- 續跑：在目標活頁簿加隱藏進度工作表，將單一來源列的完成標記和量測資料一同原子保存。實作契約見 `architecture-plan-air-hose-date-batch.md`。

## 安全性與隱私

- 身分驗證：沿用 `.env` 與 `MMISSession`，不新增憑證來源。
- 權限：只使用現有唯讀定期檢修查詢事件。
- 敏感資料：不輸出密碼、cookie、token 或 session state；本機 Excel 權限沿用 Windows 檔案權限。
- 濫用情境：輸入檔案路徑固定且非由外部輸入組合；讀取前驗證檔案與工作表；以原子替換避免半寫入目標活頁簿。

## 驗收標準

- 以臨時活頁簿中的多筆來源記錄驗證欄位對應與多筆量測展開。
- 查詢失敗會重試三次，最後失敗列保持可續跑，其他來源列仍會處理。
- 中斷後重跑會略過已完成工作單並重新處理未完成工作單。
- 成功零筆與不支援車型都能辨識為完成狀態。
- 輸出檔案保存失敗時，不破壞上一份可讀活頁簿。
- 輸入或表頭不符時，不修改目標活頁簿。
- 所有新增行為通過離線測試、安全檢查與獨立架構／安全／測試審查。

## 驗證計畫

- 單元測試：來源驗證、欄位映射、多筆記錄、零筆、不支援、重試、失敗續跑、原子保存、來源變更與重新執行。
- 整合測試：使用臨時 openpyxl 活頁簿和 stub query，驗證可見輸出和續跑狀態。
- E2E：離線驗證與審查通過後，以使用者指定工作簿執行即時 MMIS 查詢；確認正式輸出內容。
- 視覺：CLI 與活頁簿，不涉及 UI 螢幕截圖；檢查實際 XLSX 工作表與資料列。
- 手動：核對執行摘要、未完成列與目標檔案可讀性。
