# 功能規格書

## Metadata

- 功能：查詢定期檢修工單明細
- 負責人：專案使用者
- 狀態：已實作；使用者於 2026-10-13 提供具體需求與錄製證據
- 風險等級：中；需使用 MMIS HTTPS 與登入 session，操作僅唯讀

## 問題與目標

以單一工作單號取得定期檢修工單「檢修記錄」頁簽中備註非空的列，減少人工逐列檢視。

## 非目標

- 不修改 MMIS 工單或檢修記錄。
- 不輸出其他頁簽、空白備註列或其他欄位。
- 不新增正式 production CLI 命令；入口為 development tool。

## 使用者故事

| 故事 | 驗收標準 |
|---|---|
| 查詢定期檢修記錄 | 指定工作單號後，stdout 為 JSON；`檢修記錄.records` 只含備註非空的列，每列有四個指定欄位。 |

## 功能需求與邊界

- 進入「定期檢修工單」後先在預設清單依工作單號篩選；只有表格與分頁計數都確認零筆，才切換「所有記錄」重查一次。
- 任何非零查詢結果都必須唯一且工作單號完全相符；表格或分頁異常不得當成零筆重查。
- 開啟「檢修回報」及「檢修記錄」，跨頁讀完工作單的作業表格。
- 備註以 `strip()` 判定是否空白；所有備註皆空白時回傳 `{"count": 0, "records": []}`。
- 兩個查詢範圍都查無工單、結果不唯一、頁簽或表格缺失、分頁不一致時輸出 JSON 錯誤並以非零狀態結束。

## 資料與安全

- 輸入：一個英數字及連字號組成的工作單號。
- 輸出：`query_name`、`query_work_order_number`、`success`、`檢修記錄: {count, records}`；record 含裝置名稱、檢修項目、回報結果、備註。
- 身分驗證：沿用 `.env`、`MMISSession`；不寫入帳密、cookie、token 或錄製 HAR。
- 畫面：無 UI 變更。

## 驗證計畫

- 合成離線測試涵蓋預設清單命中、確認零筆後重查、兩個範圍皆零筆、非完全相符結果不得重查，以及原有跨頁、全部空白、分頁缺失、無效參數。
- 以指定錄製 DOM 驗證 58 筆中有一筆非空備註。
- 以預設清單與「所有記錄」各一張工單執行即時唯讀查詢；全套 pytest 與編譯檢查。

## 2026-10-27 新增：查詢定期檢修工單空氣軟管日期

- 使用者輸入一個工作單號，工具先依工單明細的「車組/車號」判斷車型，再讀取「檢修回報」頁籤中的「附表一」。
- 車號為 EMU6 開頭時使用「檢查項目」關鍵字「安裝日期」；EMU7、EMU8 開頭時使用「空氣軟管」。
- 其他車型不視為查詢錯誤，JSON 回傳 `success: true`、`supported: false` 與 `message: "此工作單非支援的車型"`。
- 支援車型的 `records` 每筆只輸出「檢查項目」與「量測值」；`count` 必須符合所有分頁資料數，空結果為 0 筆。
- 命令為 `python -m tools.mmis_development.query_periodic_inspection_work_order_air_hose_date <工作單>`。
- 非目標：修改附表資料、提供瀏覽器自動化，或支援其他車型。
- 驗收依據：指定 Recorder 中的 EMU813 查詢流程與 13 筆附表一紀錄；600／700 型映射依明確需求並由離線契約測試驗證。
- 架構與安全邊界見 `architecture-plan-air-hose-date.md`，本次實作任務見 `task-cards/air-hose-date.md`。
