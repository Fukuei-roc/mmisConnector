## 目標與情境包

- 目標：在日檢工單明細 JSON 的「工作單狀態」後加入「待簽核人」。
- 相關檔案：`daily_inspection/reader.py`、`temporary_repair/reader.py`、development tool 與對應測試。
- 既有模式：臨時檢修工單從「核簽記錄」的「核簽流程」讀取目前進行者，跨頁後去重排序。
- 假設：兩種工單使用相同的核簽流程表格契約；live 指定工單驗證此假設。
- 未知事項：其他日檢工單的核簽頁簽是否有不同的表格布局。
- 允許變更：上述 reader、共用核簽解析模組、日檢 development tool、測試及本 Epic 文件。
- 不得觸碰：`.env`、錄製檔、MMIS 遠端資料及無關功能。
- 驗證：日檢與臨時檢修測試、完整 pytest、編譯檢查及指定 live CLI。
- 情境預算：讀取專案地圖、流程、兩種 reader、相關測試與既有功能規格；未搜尋無關 app 或全庫錄製流量。

## 需求與驗收標準

- 「待簽核人」緊接「工作單狀態」，格式為去重排序的姓名陣列。
- 「核簽中」讀取全部核簽流程分頁；其他狀態回傳 `[]`，不查核簽頁簽。
- 空姓名、缺欄或不完整分頁回傳安全錯誤。
- 指定 CLI 成功讀取 `115-1A-78885`；臨時檢修既有行為無回歸。

## 實作與驗證契約

- 共用表格解析和分頁規則；日檢 reader 在既有頁簽讀取後取得核簽資料。
- 只向 CLI JSON 加入一個欄位，不變更輸入參數、驗證規則或遠端資料。
- 以測試涵蓋核簽中、非核簽中、欄位順序及臨時檢修回歸。
- UI、遷移、型別建置及截圖不適用。
